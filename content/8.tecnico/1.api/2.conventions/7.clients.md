---
title: 'Clients: which Auth0 app calls the api'
description: 'The x-merkaly-client header and the Auth0 app checked on each surface.'
---

Every frontend sends its Auth0 client id in the **`x-merkaly-client`** header (added by
`@merkaly/nuxt`). The api uses it to **identify** the caller in the logs (the Auth0 app name, never a
header the caller writes) and to **protect** each surface: `/admin/...` only accepts the app named
`admin.merkaly.<tld>`. When the request is authenticated, the token or session must also have been
issued to that same app (`azp` claim, copied by `AppStrategy` to `request.auth.clientId`).

## Pieces

| Piece | File | Role |
| --- | --- | --- |
| `ClientService` | `src/infrastructure/services/client.service.ts` | Builds and holds the `client_id -> Auth0 app name` map |
| `ClientMiddleware` | `src/infrastructure/middlewares/client.middleware.ts` | Names the caller in the log and checks the header against the route, before routing |
| `ClientTokenGuard` | `src/infrastructure/guards/client.token.guard.ts` | With a token, checks that its `azp` is the app of the header |
| `Auth0Service.clients` | `src/infrastructure/services/auth0.service.ts` | Management API `clients` resource |
| `AppConfig.CLIENT` | `src/app.config.ts` | Header name and the `MERKALY_CLIENT_REQUIRED` flag |

`ClientMiddleware` is a middleware, not a guard, because Nest runs guards only after a route
matched: a bot calling a route that does not exist (`/admin/session/properties`) would get a 404
without ever being identified. `ClientTokenGuard` stays a guard because the token is validated by
`AppGuard`; it is a global `APP_GUARD` registered right after `AppGuard` (Nest runs global guards in
registration order). Keep that order if the providers list changes.

## How the map is built

- Only Auth0 applications named **`<surface>.merkaly.<tld>`** count (`^([a-z0-9-]+)\.merkaly\.`,
  case-insensitive). The surface is the first label: `admin.merkaly.io` and `admin.merkaly.test`
  are both `admin`. Other names (the Management M2M app, tests) are ignored.
- There is no hardcoded list of surfaces: a route prefix is checked when some app has that surface
  (compared in lowercase, since Express routes `/ADMIN` like `/admin`). `/auth` is always checked.
  `/docs`, `/assets` and anything without an app are untouched.
- The map is loaded **once at boot** (`onApplicationBootstrap`) with
  `GET /api/v2/clients?fields=client_id,name` and kept in memory. There is no periodic refresh:
  after renaming or adding an app in Auth0, restart the api.
- The Management M2M app (`AppConfig.AUTH0.client`) needs the **`read:clients`** scope.

## Local cache

- Outside production (`AppConfig.ENV.isProduction` false) the map is saved to
  **`.cache/auth0.clients.json`** (gitignored) and read on boot, so `nest --watch` restarts call Auth0
  only once. Delete the file to force a reload.
- Shape: an object `client_id -> app name`, for example `{ "AbC123...": "admin.merkaly.test" }`.
- An empty map is never written, and a file with no valid app name is ignored: the next boot asks
  Auth0 again.
- Production (Railway, ephemeral disk) keeps the map in memory only.

## Rules

| Request | Log origin | Result |
| --- | --- | --- |
| Route prefix without an app (`/docs`, `/assets`) | unchanged | Untouched |
| No usable map (Auth0 failed, no `read:clients`, zero named apps) | unchanged | Allowed (fail-open) |
| Known app on its own surface, or any known app on `/auth/*` | Auth0 app name | Allowed |
| Known app on another surface | Auth0 app name | 428 |
| Header unknown or repeated | `Origin` host, else the IP | 428 |
| Header missing on `/auth/*` | `Origin` host, else the IP | 428, even with the flag off |
| Header missing, `Origin` is a merkaly host (`*.merkaly.<tld>`) | `Origin` host | 428, even with the flag off |
| Header missing, other or no `Origin`, `MERKALY_CLIENT_REQUIRED=false` (default) | `Origin` host, else the IP | Allowed |
| Header missing, `MERKALY_CLIENT_REQUIRED=true` | `Origin` host, else the IP | 428 |
| Authenticated, `azp` differs from the header | Auth0 app name | 428 |
| Token without `azp`, or a session without `clientId` | Auth0 app name | 401 (`AppStrategy`, `SessionService`) |

Every case that does not match an app adds a **warn** note to the request log line, so the line is
logged as a warning and says why: `no x-merkaly-client (allowed, rollout)`,
`no x-merkaly-client on /auth`, `no x-merkaly-client from a merkaly origin`, `unknown x-merkaly-client: <value>`,
`store.merkaly.io cannot call /admin`,
`token of another app: azp=<app>`. Rejections answer **428 Precondition Required** (`ClientRequiredException` in `src/infrastructure/utils/client.ts`), so they never mix with the 403 of permissions; the body never says which check failed.

The `Origin` header can be written by anyone: a bot can show `admin.merkaly.io` there. Only the
Auth0 app name is proof; the warn note marks the lines where there is none. Our apps always send
the header, so a merkaly `Origin` without it is rejected right away.

**Deploy order:** the apps must run a `@merkaly/nuxt` version that sends the header **before** this
api is deployed; an app still on an older version is rejected (its `Origin` is a merkaly host).

## Rollout flag

`MERKALY_CLIENT_REQUIRED` (env, `true` or unset) decides what happens when the header is missing.
Leave it unset until every frontend runs a `@merkaly/nuxt` version that sends `x-merkaly-client`,
watch the `no x-merkaly-client` warnings from real apps disappear, then set it to `true`.

## Failures never block the boot

- If Auth0 fails (network, missing `read:clients`), the api still starts: it logs an error and
  retries in the background with exponential backoff (5 s up to 15 min). Until a load succeeds the
  check is fail-open.
- A successful load with **zero** named apps counts as "no map" (fail-open, one warning), so the api
  can be deployed before the apps are named.

## Adding a new app

1. Create the Auth0 application named `<surface>.merkaly.<tld>` (Auth0 config lives in
   auth.merkaly.io, see its [tenant setup](/tecnico/auth/tenant-setup)). Its route prefix must be `/<surface>`.
2. Restart the api (locally, delete `.cache/auth0.clients.json` first).
