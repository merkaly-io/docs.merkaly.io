---
title: 'Cross-collection access'
description: 'Another entity''s collection is reached through that entity''s repository.'
---

A service or repository that reads or writes **another entity's collection** goes through **that
entity's repository**: a named method there (see [layers.md](/tecnico/api/conventions/layers)). Never through the
connection.

```ts
// No
this.$mongo.connection.model(OrderSaleSchema.name).exists({ ... });
this.$repository.$builder.db.model(AppSchemas.contact.customers).find({ ... });
this.$repository.$builder.db.collection(AppSchemas.finance.payments).aggregate([...]);

// Yes
this.$sales.hasSalesWithProduct(productId);
this.$customers.getCustomersByName(name);
this.$payments.getPaymentsReport(filters);
```

## Why

The api opens one Mongoose connection per organization database (`useDb`). A model exists on that
connection only once it was registered **with its schema** (`MongoService.schema()` does it the
first time a repository uses `$builder`). `connection.model(name)` without a schema only finds an
already registered model; otherwise Mongoose throws `MissingSchemaError` (500, intermittent: it
depends on what ran on that org since the last restart). Raw `db.collection(name)` avoids the error
but skips the repository layer (schema casting, soft delete conventions, logging).

The repository's `$builder` always registers its own schema, so it never fails this way.

## Getting the repository

1. **Inject it** (`@Inject() private readonly $customers: ContactCustomerRepository`): the consumer's
   module imports the module that exports it.
2. **When that import would close a module cycle, move the cross-domain step up**, never resolve
   the repository lazily with `ModuleRef` and never chain `forwardRef`:
   - a check that needs both domains goes in a flow of a module that imports both (e.g.
     `CatalogProductDeleteFlow` in `CatalogModule` reads the order repositories, while the order
     modules import only `CatalogProductModule` and `CatalogVariantModule`);
   - a module that does not use what it imports drops that import (e.g. `FinancePaymentModule` no
     longer imports `OrderSaleModule`, so `FinanceWithdrawalModule` can import it).

Repositories never inject another repository: a repository importing a repository that
injects it back creates a file import cycle, and property injection then reads an `undefined` type.

## `$lookup`

`$lookup.from` only needs the collection name: use the `AppSchemas.*` constant (or the repository's
`$builder.collection.name`). Never `db.model(name).collection.name`.

## Exceptions

- `MongoService` and `AbstractRepository` internals (they own model registration).
- `sequence.plugin.ts`: a Mongoose plugin hook outside Nest DI, it bumps the organization sequence
  document directly.
- `OrderSeeder.inventory()`: lists every collection to count documents, not entity access.
