**Fecha**: 2026-11-25 · **Estado**: aceptada

## Contexto

El cobro se describía con varias banderas y con el estado crudo del proveedor, y distintas partes del api decidían con combinaciones distintas.

## Decisión

Cada [cobro](/glosario/payment-charge) tiene un solo estado, mutuamente excluyente, y es el único campo con el que se decide. payments lo traduce desde el proveedor y el api deriva el resto: se puede borrar si es `PENDING` o `EXPIRED`; está pagado (y se reembolsa en línea) si es `APPROVED` o `SETTLED`. `MANUAL` nunca cuenta como pagado: espera revisión humana. Un estado desconocido es `IN_PROCESS`, nunca pagado.

## Consecuencias

- No hay estado nulo ni desconocido, y no hay un campo `deleted` aparte (`CANCELLED`).
- El estado crudo del proveedor se guarda solo para log y auditoría.
- Ver el ciclo de vida completo en [Estado del cobro](/ciclos/charge-status).
