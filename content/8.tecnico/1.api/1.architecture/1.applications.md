Where an HTTP route lives depends on who calls it. Who each app is for and who may open it:
[docs.merkaly.io/tienda](https://docs.merkaly.io/tienda) and [docs.merkaly.io/identidad](https://docs.merkaly.io/identidad).

| Location | Mounted at | What goes there |
| --- | --- | --- |
| `src/application/<app>` (`admin`, `store`, `www`, `dashboard`) | `/<app>/...` | Use cases of one surface. Each module extends `AbstractRouter` and is listed in `router` (`app.module.ts`), so `RouterModule` prefixes its routes and its guard (`AdminGuard`, `StoreGuard`...) applies. |
| `src/application/auth` | `/auth/...` (`/auth/session`, `/auth/me`...) | Auth and user routes every app calls. `AuthModule` is listed in `router` like the apps, but it has no surface guard: frontends call it with `global: true` (no app prefix) and the path `/auth/...`. |
| `src/app.controller.ts` | `/assets/*key` | Only the public file delivery of local uploads (browser `<img src>`, no tenant host). Nothing else. |

## `src/application/auth`

- `controllers/auth.session.controller.ts`: `GET /auth/token`, `POST|GET|DELETE /auth/session` (session cookie).
  The `merkaly.sid` cookie is an opaque random id (32 bytes, base64url) that names the session file
  (`.cache/sessions/<host>/<id>.json`); it carries no user or organization data. `POST` keeps the
  browser's session when user, organization and app match, otherwise it issues a new id.
- `controllers/auth.identity.controller.ts`: `GET /auth/connections`, `GET|POST|DELETE /auth/identities/:provider/:userId`
  (`AccountConnectionService`, `AccountIdentityService`).
- `controllers/auth.password.controller.ts`: `POST|PUT /auth/password` (Auth0 change password ticket,
  `AccountPasswordCreateFlow` and `AccountPasswordUpdateFlow`) and `POST /auth/me/password-changes`
  (Auth0 emails the link, `AccountPasswordChangeFlow`).
- `controllers/auth.profile.controller.ts`: `GET|PATCH /auth/me`, `PUT|DELETE /auth/me/avatar`,
  `POST /auth/me/email-verifications` (`AccountUserUpdateFlow`, `AccountAvatarUpdateFlow`).
- Every controller extends `AuthController`, which only sets the Swagger group (`auth`), and calls
  one flow or one service.

Domain logic stays in `src/domain/account` (flows in `flows/`, services in `services/`).
`AppGuard` (global `APP_GUARD`) and `SessionService` are infrastructure and apply to these routes
like to any other; `AppGuard` treats `POST /auth/session` as the bearer exchange. `ClientMiddleware`
(before routing) and `ClientTokenGuard` (global, after `AppGuard`) identify and check the calling app
on every surface and `/auth` route, see
[clients.md](/tecnico/api/conventions/clients).

## Adding a route

1. One surface uses it: its `src/application/<app>` module (prefixed, surface guard).
2. Every app uses it with the logged user, with no surface: `src/application/auth` (`/auth/...`).
3. Never add routes to `src/app.controller.ts`.
