---
title: payments no guarda estado
description: Decidida el 2026-11-22. El api guarda todo y payments solo habla con el proveedor.
---

**Fecha**: 2026-11-22 · **Estado**: aceptada

## Contexto

El api hablaba directo con Asaas: conocía sus estados, sus unidades y sus credenciales. Cambiar de proveedor obligaba a tocar el corazón del negocio.

## Decisión

[payments](/glosario/payments) es el único servicio que habla con el proveedor, y no tiene base de datos. El [api](/glosario/api) guarda todos los registros (cobros, reembolsos, retiros, contracargos), las credenciales de cada subcuenta y los ids del proveedor, y se los manda en cada invoke. Las referencias (`<orgId>:<saleId>`) las arma y las lee solo el api.

## Consecuencias

- El api nunca ve un nombre, un estado ni una credencial del proveedor, y nunca decide con datos crudos.
- Un proveedor nuevo es un gateway nuevo en payments, sin cambios en el api.
- Como un invoke perdido no se reintenta, toda escritura tiene que poder repetirse sin efecto doble.
