How pages relate to the app shell (sidebar + header + content area).

## Decision

The layout is mounted **once** in `app.vue` and stays mounted across navigation:

```vue
<!-- app/app.vue -->
<MKApp>
  <NuxtLoadingIndicator color="var(--bs-primary)" :height="3" />
  <NuxtLayout>
    <NuxtPage />
  </NuxtLayout>
</MKApp>
```

Pages **must not** wrap themselves in `<NuxtLayout>`.

### Why

When each page renders its own `<NuxtLayout>`, navigating unmounts and
remounts the whole shell (sidebar + header included), so the screen flashes
blank on every route change. A single persistent `<NuxtLayout>` swaps only the
`<NuxtPage>` content, so the shell never flashes.

## How a page talks to the shell

Because the shell is now an **ancestor** of the page (not a child), a page can
no longer pass props/slots into it. Use the channel that matches the need:

| Need | Channel | How |
|---|---|---|
| Page body | Default slot | Just render the page content (automatic). |
| Toolbar (header actions) | Teleport | `<UiPageToolbar>` → outlet `#layout-toolbar`. |
| Data loading | Page-level gate | wrap content in `<UiPageLoader :loading="reading">`. |
| Page actions (back, save, next step) | Sticky bottom bar | last `BCol.sticky-bottom` with an opaque `BCard`. |
| Auth / session / user | Global gate (upstream) | handled by `MKApp` — pages don't mount until auth resolves. |
| Which layout | Route meta | `definePageMeta({ layout: 'auth' })`. |

### Toolbar — `<UiPageToolbar>` (project-specific)

The layout exposes an outlet in the section bar (white ribbon under the top bar), right of the breadcrumb and title:

```vue
<!-- app/layouts/default.vue -->
<div class="mk-sectionbar">
  <BContainer class="mk-sectionbar-inner" fluid="xxl">
    <BaseBreadcrumb />
    <div id="layout-toolbar" class="mk-page-toolbar" />
  </BContainer>
</div>
```

Pages teleport their toolbar into it:

```vue
<UiPageToolbar>
  <UiButtonIcon variant="primary" :text="$t('actions.add')" icon-name="plus" @click="openModal()" />
</UiPageToolbar>
```

`<UiPageToolbar>` is just `<Teleport defer to="#layout-toolbar"><slot /></Teleport>`.
`defer` waits for the outlet (rendered by the layout) to exist before resolving.

### Data loading — `<UiPageLoader>`

The shell must **not** gate a page's mount on the page's own loading flag —
that is circular and loops forever (see anti-patterns). Instead the page stays
mounted and gates **its own content** until data is ready:

```vue
<UiPageLoader :loading="reading">
  <OrderSaleTransactionForm v-model="order" />
</UiPageLoader>
```

`<UiPageLoader>` shows a spinner while `loading`, else its slot. Gating here
matters: detail forms snapshot their model in `setup` (e.g.
`useValidator(order.value)`), so they must mount only once the entity is
present, not empty.

This is a 1:1 replacement of the old `<NuxtLayout :loading="reading">` wrapper —
not new boilerplate. List pages need no wrapper at all.

> Auth/session/user are gated **upstream** in `MKApp` (`v-if="isLoading"`), so a
> page never mounts — and never fetches — until auth is resolved. `UiPageLoader`
> only covers the page's own entity fetch.

### Page actions — sticky bottom bar

Detail and edit pages put their page actions (back on the left, cancel / save /
next step on the right) in a bar stuck to the bottom of the viewport, as the
last column of the page:

```vue
<BCol class="sticky-bottom" cols="12">
  <BCard class="rounded-bottom-0 bg-secondary-subtle">
    <div class="d-flex justify-content-between align-items-center gap-3 flex-wrap">
      <UiButtonIcon :text="$t('actions.back')" icon-name="arrow-left" to="/sales/orders" variant="light" />

      <div class="d-flex flex-wrap gap-3">
        <UiButtonSubmit :loading="loading" :text="$t('actions.save')" />
      </div>
    </div>
  </BCard>
</BCol>
```

- Secondary actions first, the primary one last.
- `bg-secondary-subtle` is required: the card background is translucent, so
  without it the content scrolling underneath shows through.
- It is the default for new detail/edit pages with actions; existing pages are
  not migrated just for this.
- Header actions that don't belong to the entity flow (import, withdraw) go in
  `<UiPageToolbar>` instead.

## Anti-patterns

- **Don't** wrap a page in `<NuxtLayout>` — reintroduces the full-shell remount/flash.
- **Don't** gate the page's mount on a signal the page itself produces. The old
  layout did `<template v-if="current?.loading"> spinner </template><slot v-else />`,
  but the page is what set `current.loading` (via `useNavigation`). With the
  persistent layout that is circular: page mounts → sets loading → layout hides
  the slot → page unmounts → loading source gone → loading clears → page mounts
  again → infinite loop (observed: 100+ mount/unmount, breadcrumbs/`<title>`
  growing each cycle). Gate the page's **content** with `<UiPageLoader>` instead;
  the page stays mounted.
- **Don't** use `setPageLayout(name, { loading })` to drive a reactive prop.
  `setPageLayout` applies `route.meta.layoutProps` at **navigation-resolution
  time**, not reactively — verified locally: the spinner stayed stuck because the
  `loading: false` update never reached the layout. It is only for choosing the
  layout dynamically at runtime.

## Migrating a page

1. Remove the `<NuxtLayout …>` wrapper; the content becomes the page root.
2. `<template #toolbar>` → `<UiPageToolbar>`.
3. `<NuxtLayout :loading="reading">` → `<UiPageLoader :loading="reading">` around the content (keep the toolbar outside it). List pages need no wrapper.
4. Non-default layout (e.g. auth) → `definePageMeta({ layout: 'auth' })`.
